# Architecture

JasinaHub is a React 18 + Vite SPA backed by Supabase (Lovable Cloud): Postgres with Row-Level Security, Auth, Storage, Edge Functions, and Realtime.

## High-level

```
 ┌───────────────┐   HTTPS    ┌──────────────────────────────┐
 │  React PWA    │ ─────────► │ Supabase (Lovable Cloud)     │
 │  (Vite + TS)  │            │  • Postgres + RLS            │
 │  shadcn/ui    │            │  • Auth (email/password)     │
 │  Tailwind     │            │  • Storage (voice-recordings)│
 │  React Query  │            │  • Edge Functions (Deno)     │
 └───────────────┘            │  • Realtime (presence)       │
         │                    └──────────────────────────────┘
         │
         └── MediaRecorder API → WebM/Opus → Storage bucket
```

See the full UML/mermaid diagrams in [README.md](../README.md#diagrams).

## Layers

| Layer | Location | Purpose |
|---|---|---|
| Routing / pages | `src/pages/` | One file per route (`Dashboard`, `Questions`, `Transcribe`, `Admin`, …) |
| Feature components | `src/components/<Feature>/` | Grouped by domain (Admin, Auth, Dashboard, Questions, Transcription, VoiceRecording) |
| UI primitives | `src/components/ui/` | shadcn/ui (Radix under the hood) |
| Hooks | `src/hooks/` | Cross-cutting: `useUserRole`, `useActivityTracker`, `usePresenceTracking`, `useHapticFeedback`, `useSwipeGesture`, `usePullToRefresh` |
| Data access | `src/integrations/supabase/client.ts` | Auto-generated Supabase client + typed schema |
| In-app test harness | `src/lib/tests/` | 14 test suites executed from the Admin → Tests tab |
| Edge functions | `supabase/functions/*` | `reset-password`, `migrate-drive-audio` |
| Migrations | `supabase/migrations/*.sql` | Ordered schema + RLS + RPC changes |

## Auth & authorization

- Email/password only. Session persisted in `localStorage`; auto-refreshed by supabase-js.
- Roles live in `public.user_roles` (never on `profiles`). `public.has_role(uid, role)` is a `SECURITY DEFINER` function used inside RLS policies to avoid recursion.
- Route guards: `ProtectedRoute` (authenticated) and `AdminRoute` (admin role).

## Voice recording pipeline

1. Volunteer grants voice-recording consent (persisted on `profiles`).
2. `MinimalRecorder` captures via `MediaRecorder` (WebM/Opus, ≤ 30 s).
3. Blob is auto-saved to `localStorage` (base64) as insurance against tab loss (`src/utils/recordingStorage.ts`).
4. On submit: upload to `voice-recordings` Storage bucket, insert row into `voice_responses`.
5. Question is retired for the user after 3 unique responses (see `get_question_counts` RPC).

## Transcription pipeline

1. Transcriber must be approved (`profiles.transcription_approved = true`).
2. `claim_random_transcription(uid)` RPC atomically claims a `voice_response` and writes a lock into `transcription_locks` (15-minute TTL).
3. Transcriber submits verbatim text; up to 3 edits before it becomes immutable.
4. Admin accepts/rejects. Accepted rows form the exportable dataset.

## Frontend state

- **Server state**: `@tanstack/react-query` for cached reads.
- **Auth state**: `AuthProvider` context (`src/components/Auth/AuthProvider.tsx`).
- **Theme**: `next-themes` (light/dark), applied via the semantic tokens in `src/index.css`.
- **PWA / offline**: `vite-plugin-pwa` service worker + `recordingStorage` fallback queue.

## Observability

- Client → `user_activity_logs` (page transitions, key events).
- Realtime presence → `usePresenceTracking`.
- Errors → `src/lib/logger.ts` (console in dev, no-op in prod build). Wire to Sentry if desired.

## Bundle

- Vite + SWC. Mermaid is lazy-loaded (only in Admin → Documentation).
- PWA precache assets under `public/`.
- `stats.html` is generated by `rollup-plugin-visualizer` on `npm run build`.
